# ADR-009: Model Ancaman Singkat

- **Status:** Diusulkan
- **Tanggal:** 2026-10-20
- **Tiket:** BOARD-2008 (spike, timebox 1 hari)
- **Pemilik:** @riziq

## Konteks

`@kujam/*` dipasang di dalam aplikasi lain (Jam Tayang dan pemakai pihak ketiga) dan menerima data dari banyak sumber: penyimpanan, server sinkronisasi, peer kolaborasi, clipboard, dan berkas impor. Dokumen ini memetakan ancaman yang relevan ke mitigasi yang sudah ada di kode, atau ke tiket bila belum ditangani. Tujuannya bukan audit penuh, melainkan memastikan setiap permukaan serangan punya pemilik.

## Batas kepercayaan

| Sumber                                                            | Dipercaya? | Alasan                                                                                                               |
| ----------------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| Kode aplikasi dan plugin (`defineElement`, `defineTool`, adapter) | Ya         | Berjalan di origin yang sama dengan hak penuh. Package tidak bisa (dan tidak berusaha) melindungi dari plugin jahat. |
| Isi dokumen (record, props, rich text, aset)                      | Tidak      | Bisa berasal dari peer, server, berkas, clipboard, atau penyimpanan lokal yang diubah.                               |
| State presence/awareness (nama, warna, kursor, coretan live)      | Tidak      | Diatur sepenuhnya oleh klien lain, tidak melewati validasi dokumen.                                                  |
| Server sinkronisasi dan storage                                   | Sebagian   | Server milik aplikasi, tetapi klien lain bisa menulis lewatnya; klien tetap memvalidasi data yang diterima.          |
| Input pengguna lokal (ketikan, paste, drag-and-drop)              | Tidak      | Paste dan drop membawa konten dari luar.                                                                             |

Konsekuensinya: setiap data yang menyeberang dari kategori "tidak dipercaya" ke DOM, canvas, store, atau jaringan wajib divalidasi atau di-escape oleh package, sedangkan keamanan kode plugin adalah tanggung jawab penulisnya (dengan panduan dari kita).

## Tiket baru (sudah dikerjakan)

Dua celah tidak punya tiket, sehingga ditambahkan ke backlog (BOARD-E20):

- **BOARD-2009: Validasi dan batas state presence dari peer (T2).** Bentuk state presence divalidasi seperti record (nama maksimal 64 karakter, warna `#rrggbb`, koordinat berhingga dalam batas wajar, seleksi maksimal sejumlah ID, coretan live maksimal `maxDrawPoints`); state yang tidak valid diabaikan per field. Opsi agar server (atau aplikasi) menimpa `user` di awareness dengan identitas hasil autentikasi, sehingga peer tidak bisa menyamar.
- **BOARD-2010: Server contoh menolak update tidak valid (T4).** `examples/hocuspocus-server` menolak (bukan hanya melaporkan) update yang membuat dokumen tidak valid, membatasi ukuran pesan, menambahkan rate limit sederhana per koneksi, dan menandai token mock sebagai khusus pengembangan (gagal start di `NODE_ENV=production` tanpa `AUTH_ENDPOINT`).

## Keputusan

1. Model kepercayaan di atas berlaku untuk semua package: **data tidak dipercaya, kode plugin dipercaya**. Setiap fitur baru yang membawa data dari dokumen, peer, atau berkas ke DOM, canvas, atau jaringan menyebut ancaman dari tabel ini di deskripsi PR-nya.
2. Ancaman berstatus Terbuka dikerjakan bersama fiturnya (T8 di 0.3, T9 dan T10 di 0.4, T15 sebelum 1.0). Kriteria keamanan di tiket fitur tersebut tidak boleh dilepas.
3. T2 (BOARD-2009) dan T4 (BOARD-2010) dikerjakan dalam rilis 0.2 karena kolaborasi realtime sudah aktif (selesai 2026-10-20).
4. Dokumen ini ditinjau ulang setiap rilis minor dan ketika permukaan baru ditambahkan (misalnya `@kujam/server`, ekspor PDF, impor Excalidraw).
